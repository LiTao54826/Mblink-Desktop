# 统一渲染管线重构 - 需求文档

## 背景

当前项目存在两套渲染管线：
- `RenderPipeline` (V1): 位于 `core/render/`，负责 DOM 同步、样式计算、布局
- `RenderPipelineV2`: 位于 `core/compositor/`，负责层树构建、光栅化、GPU 合成

两套系统职责分散，通过 `WindowCompositorAdapter` 适配，导致：
- 代码结构混乱，调用链复杂
- Window 类承担过多职责
- 组件间耦合度高，难以维护

## 目标

将两套渲染管线合并为统一的 `UnifiedRenderPipeline`，实现：
1. 单一入口处理完整渲染流程
2. 简化 Window 类
3. 清晰的阶段划分和职责边界

## 功能需求

### FR-1: 统一渲染入口
- 提供单一 `ProcessFrame()` 方法完成所有渲染工作
- 支持增量更新和全量更新两种模式
- 自动检测脏状态，跳过不必要的阶段

### FR-2: 完整渲染阶段
管线需包含以下阶段：
1. **DOM 同步**: 检测 DOM 变化，同步到渲染树
2. **样式计算**: 重算脏节点样式
3. **布局**: 计算节点位置和尺寸
4. **层树构建**: 构建/更新合成层树
5. **光栅化**: CPU 光栅化脏层
6. **合成**: GPU 合成到屏幕

### FR-3: 脏标记系统
- 支持细粒度脏标记：样式、布局、绘制
- 脏标记自动向下传播
- 支持强制全量更新

### FR-4: 滚动优化
- 滚动时只更新层偏移，不重新光栅化
- 支持滚动容器注册和管理
- 支持固定定位元素

### FR-5: 动画优化
- transform/opacity 动画直接在合成阶段处理
- 支持动画帧批处理
- 动画属性变化不触发重新光栅化

### FR-6: 属性树系统
- 集成现有属性树系统
- 支持 transform、clip、effect、scroll 四种属性树
- 支持直接属性更新（绕过光栅化）

### FR-7: 配置和调试
- 支持运行时配置切换
- 支持层边界显示（调试）
- 提供帧统计信息

## 非功能需求

### NFR-1: 性能
- 合并后性能不低于现有实现
- 减少不必要的内存分配
- 支持帧跳过优化

### NFR-2: 兼容性
- 保持现有 API 兼容
- 渐进式迁移，不破坏现有功能

### NFR-3: 可维护性
- 清晰的代码结构
- 完善的注释和文档
- 单元测试覆盖

## 约束

- 使用 C++17 标准
- 依赖 Skia 图形库
- 保持与现有 DOM、布局引擎的接口兼容
